# AWS CloudFormation - IAM User 생성

CloudFormation을 이용해 IAM User를 생성하고, AWS Console 로그인 정보와 CLI/SDK에서 사용할 Access Key를 구성한다.

## 1. 전체 구조

```text
CloudFormation Stack
│
├── Parameters
│   ├── UserName
│   └── UserPassword
│
└── Resources
    │
    ├── IAMUser
    │   ├── IAM User 생성
    │   ├── Console Password 설정
    │   └── AdministratorAccess 부여
    │
    ├── IAMUserAccessKey
    │   └── Access Key / Secret Access Key 생성
    │
    └── AccessKeySecretManager
        └── Access Key / Secret Access Key 저장
```

전체적인 생성 흐름은 다음과 같다.

```text
CloudFormation Stack 생성
        │
        ├── UserName 입력
        │
        └── UserPassword 입력
                │
                ▼
          ┌─────────────┐
          │   IAM User  │
          └─────────────┘
                │
                ├── Console Login 설정
                │
                ├── AdministratorAccess 부여
                │
                └── Access Key 생성
                        │
                        ▼
                ┌─────────────────┐
                │ Secrets Manager  │
                └─────────────────┘
                        │
                        └── Access Key 정보 저장
```

---

## 2. Parameters

`Parameters`는 CloudFormation Stack을 생성할 때 사용자로부터 값을 입력받는 영역이다.

```yaml
Parameters:
  UserName:
    Description: IAM User Name.
    Type: String

  UserPassword:
    Description: IAM User Password.
    Type: String
    NoEcho: true
```

### UserName

```yaml
UserName:
  Description: IAM User Name.
  Type: String
```

IAM User의 이름을 입력받는다.

예를 들어 다음과 같이 입력할 수 있다.

```text
UserName = yuna-admin
```

이후 IAM User의 이름으로 `yuna-admin`이 사용된다.

### UserPassword

```yaml
UserPassword:
  Description: IAM User Password.
  Type: String
  NoEcho: true
```

IAM User의 AWS Console 로그인 비밀번호를 입력받는다.

#### NoEcho

```yaml
NoEcho: true
```

`NoEcho`를 사용하면 CloudFormation 콘솔 등의 화면에서 Parameter의 실제 값이 노출되지 않도록 할 수 있다.

```text
Password: ********
```

> `NoEcho`는 화면 노출을 방지하기 위한 옵션이며, Secret을 별도의 보안 저장소에 저장하는 기능은 아니다.

---

## 3. Resources

`Resources`에서는 CloudFormation이 실제로 AWS 리소스를 생성한다.

---

## 3-1. IAM User 생성

```yaml
IAMUser:
  Type: AWS::IAM::User
  Properties:
    UserName: !Ref UserName
    LoginProfile:
      Password: !Ref UserPassword
    ManagedPolicyArns:
      - arn:aws:iam::aws:policy/AdministratorAccess
```

`AWS::IAM::User`를 이용해 IAM User를 생성한다.

### UserName

```yaml
UserName: !Ref UserName
```

`!Ref`를 이용해 `Parameters`에서 입력받은 `UserName` 값을 참조한다.

예를 들어:

```text
UserName = yuna-admin
```

으로 입력하면:

```yaml
UserName: !Ref UserName
```

은 실제로 다음과 같이 동작한다.

```yaml
UserName: yuna-admin
```

즉,

```text
Parameter UserName
        │
        │ !Ref
        ▼
IAM User의 UserName
```

구조이다.

---

## 3-2. LoginProfile - AWS Console 로그인 설정

```yaml
LoginProfile:
  Password: !Ref UserPassword
```

IAM User가 AWS Management Console에 로그인할 때 사용할 비밀번호를 설정한다.

```text
AWS Management Console
        │
        ▼
IAM User 로그인
        │
        ├── UserName
        │
        └── Password
```

---

## 3-3. ManagedPolicyArns - 관리자 권한 부여

```yaml
ManagedPolicyArns:
  - arn:aws:iam::aws:policy/AdministratorAccess
```

IAM User에게 AWS에서 제공하는 `AdministratorAccess` 관리형 정책을 연결한다.

`AdministratorAccess`는 AWS 리소스를 광범위하게 관리할 수 있는 관리자 권한이다.

```text
IAM User
   │
   └── AdministratorAccess
          │
          ├── EC2
          ├── S3
          ├── RDS
          ├── Lambda
          ├── IAM
          ├── CloudFormation
          └── 기타 AWS 리소스
```

> ⚠️ `AdministratorAccess`는 매우 강력한 권한이므로 실제 운영 환경에서는 필요한 권한만 부여하는 것을 권장한다.

---

## 4. IAMUserAccessKey - Access Key 생성

```yaml
IAMUserAccessKey:
  Type: AWS::IAM::AccessKey
  Properties:
    UserName: !Ref IAMUser
```

`AWS::IAM::AccessKey`를 이용해 IAM User가 AWS CLI 또는 AWS SDK를 사용할 수 있도록 Access Key를 생성한다.

AWS Access Key는 다음 두 가지 정보로 구성된다.

```text
Access Key ID
+
Secret Access Key
```

예시:

```text
Access Key ID
AKIA................
```

```text
Secret Access Key
xxxxxxxxxxxxxxxxxxxxxxxx
```

### UserName

```yaml
UserName: !Ref IAMUser
```

`!Ref IAMUser`를 이용해 앞에서 생성한 `IAMUser` 리소스를 참조한다.

`AWS::IAM::User`에서 `Ref`를 사용하면 생성된 IAM User의 이름을 반환한다.

따라서:

```yaml
UserName: !Ref IAMUser
```

은 다음과 같은 의미이다.

```text
IAMUser 리소스
      │
      ▼
생성된 IAM User의 이름
      │
      ▼
해당 User에 Access Key 생성
```

---

## 5. AccessKeySecretManager - Secrets Manager 저장

```yaml
AccessKeySecretManager:
  Type: AWS::SecretsManager::Secret
  Properties:
    Name: !Sub ${IAMUser}-credentials
    SecretString: !Sub |
      {
        "accessKeyId": "${IAMUserAccessKey}",
        "secretAccessKey": "${IAMUserAccessKey.SecretAccessKey}"
      }
```

AWS Secrets Manager에 Access Key와 Secret Access Key를 저장한다.

Access Key 정보는 민감한 인증 정보이므로 코드에 직접 작성하거나 Git에 저장하지 않고 Secrets Manager를 이용해 관리할 수 있다.

---

## 5-1. Secret Name

```yaml
Name: !Sub ${IAMUser}-credentials
```

`!Sub`는 문자열 안에 다른 값을 삽입할 때 사용하는 CloudFormation 내장 함수이다.

예를 들어 IAM User가:

```text
yuna-admin
```

이라면:

```yaml
${IAMUser}-credentials
```

는 다음과 같이 구성된다.

```text
yuna-admin-credentials
```

---

## 5-2. SecretString

```yaml
SecretString: !Sub |
  {
    "accessKeyId": "${IAMUserAccessKey}",
    "secretAccessKey": "${IAMUserAccessKey.SecretAccessKey}"
  }
```

Secrets Manager에 Access Key 정보를 JSON 형태로 저장한다.

저장되는 데이터의 형태는 다음과 같다.

```json
{
  "accessKeyId": "AKIA....",
  "secretAccessKey": "xxxxxxxx...."
}
```

### 저장되는 값

| Key               | 설명                         |
| ----------------- | ---------------------------- |
| `accessKeyId`     | IAM User의 Access Key ID     |
| `secretAccessKey` | IAM User의 Secret Access Key |

> `secretAccessKey`는 민감한 인증 정보이므로 외부에 노출하거나 Git Repository에 직접 저장하지 않도록 주의한다.

---

## 6. CloudFormation 주요 문법

### `!Ref`

다른 Parameter 또는 Resource의 값을 참조할 때 사용한다.

```yaml
UserName: !Ref UserName
```

```text
Parameters.UserName
        ↓
      !Ref
        ↓
IAMUser.UserName
```

또한 Resource를 참조할 수도 있다.

```yaml
UserName: !Ref IAMUser
```

---

### `!Sub`

문자열 내부에 Parameter 또는 Resource 값을 삽입할 때 사용한다.

```yaml
Name: !Sub ${IAMUser}-credentials
```

예:

```text
IAMUser = yuna-admin

        ↓ !Sub

yuna-admin-credentials
```

---
